# Ledger: climb 2, all remaining SL-COMP benchmarks

Started 2026-10-20. Previous ledgers: `ledgers/work-ledger-climb.md` (steps 1-22, T1-T6), `ledgers/work-ledger-post-climb.md` (baseline reset 2026-10-19).

## Goal

Grow the set of SL-COMP benchmarks that `xsearch` proves (and refutes) beyond the two divisions covered today (`qf_shls_entl` 296, `qf_shid_entl` 312: 454 of 608 provable, all proved; valid time 17.6 s at the 2026-10-19 baseline, `evolve/ref/baseline.csv`), one algorithmic improvement after another, and keep pushing total time down. S2S solved all of SL-COMP 2019 in about 60 s; aim lower.

Divisions not yet covered: `qf_shlid_entl` 60, `qf_shidlia_entl` 61, `shid_entl` 73, `shidlia_entl` 181, `onprob_qf_shid_entl` 11, and the sat divisions `qf_shls_sat` 110, `qf_shid_sat` 99, `qf_bsl_sat` 46, `qf_bsllia_sat` 24, `qf_shidlia_sat` 33.

End state (user, 2026-10-20): the result must be one proper algorithm, not a collection of shape-specific special cases. The proof climb may add mechanisms quickly, but it is followed by a mandatory consolidation phase (backlog C1 and successors): a series of passes that fold the descriptor kinds and planning passes into one indexed-segment abstraction with one lemma family and one planner, each pass verified by the full bench with zero losses, and only then the time passes.

Scope rule (user, 2026-10-20): the goal is the best separation-logic automation. Divisions whose difficulty is a background theory (LIA, bitvectors) are handled by delegating the pure residue to an existing Lean closing tactic (`omega`, `bv_decide`, `simp`), not by building arithmetic reasoning into `xsearch`; the separation-logic part around them is in scope. Reaffirmed 2026-10-21: no theory-specific optimisation passes either; the only arithmetic-side work is delegating well (trimmed goal-local context, omega's MetaM core, no repeated calls per obligation). Length invariants and profiles of segments are separation-logic content and may be proved generically once.

## Acceptance criteria

- Monotone per step: full bench on every covered division, diff against the previous accepted CSV by file name: lost list empty; proved (or refuted) count not lower; no problem newly over 3500 ms.
- Standing rules from the previous ledgers hold: keep the `xsimpl` interface and speed it up internally; general tactics only, no hard-coded predicate names, shapes, or constants tuned to problems; no `sorry`, axioms, `native_decide`, `unsafe`; no comments or docstrings in code.
- Commit and push after each milestone; `telegram-ping` the user after each, stating how the proved count climbed (before → after, out of 798).

## How to use this ledger

Read this file fully, then `git status` and `git log --oneline -5`. An uncommitted `Sep/` edit means a subagent step was in flight: rebuild (`timeout 900 lake build Sep Bench bench`), rerun the bench, and diff before trusting it. Bench: `timeout 2400 lake exe bench --dir <d> ... --timeout 5000 --csv evolve/ref/<name>.csv`; `python3 scripts/bench-report.py` diffs CSVs. Subagents: Opus for implementation, Sonnet for refactoring; each gets the repo path, the rules above, the build and bench commands with timeouts, the previous accepted CSV, one technique, and the acceptance criterion; it reports proved total, gained and lost lists, and directory times. Before work: add a backlog item; after: a numbered history entry saying what and why (not how), with counts and times; mark dead ends DEAD END.
